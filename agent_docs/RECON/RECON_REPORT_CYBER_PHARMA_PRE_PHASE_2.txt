  Section 3 — Auth Pattern

  - User read via: useAuthStore (client) + supabase.auth.getUser() (server actions, navbars, Profile pages). Both
  patterns coexist; useAuthStore is the persistent client state, Supabase calls are the auth-source-of-truth.
  - Role resolved via: getUserRole(userId) queries public.user_roles table; AppRole enum at src/utils/app-role.ts.
  Layouts call protectPage([AppRole.X]) from src/utils/supabase/actions.ts.
  - Existing auth service: NONE. No src/services/auth.ts or similar. src/services/ is empty. Option-(b) ruling
  honored end-to-end. Don't author a service wrapper.
  - user_metadata role smells: 0. All user_metadata reads in code are for full_name (display name), NOT role. Test
  fixtures contain role: 'member' in user_metadata mock data — acceptable for unit tests.
  - protectPage route gates: in (members)/layout.tsx ([AppRole.MEMBER]) and (admin)/layout.tsx ([AppRole.ADMIN]).
  Tested by src/__tests__/actions.test.ts (7 cases including superadmin negative cases).
